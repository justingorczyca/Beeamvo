# Project notes

Architecture notes for contributors and AI coding agents.

- The Flutter application and tests live in `frontend/`.
- CI verification: `dart format --output=none --set-exit-if-changed lib test`, `flutter analyze`, and `flutter test`, run from `frontend/`. CI pins Flutter 3.47.4 and resolves dependencies with `flutter pub get --enforce-lockfile`.
- With dependencies already resolved, use `flutter analyze --no-pub` and `flutter test --no-pub` to avoid incidental lockfile updates.
- Cloud transcription has two provider implementations: `GeminiInteractionsService` uses the Gemini Interactions API; `VertexAiService` uses Vertex `generateContent`. `CloudTranscriptionService` is the shared transcript-validation boundary.
- Pipeline roles: the first pass (audio) is local Whisper or a provider in `AppConfig.firstPassAudioProviders` (Gemini, Vertex or Codex OAuth). Codex OAuth sends speech to ChatGPT's `/backend-api/transcribe` endpoint using the transcription-only `chatgpt-transcribe` model; it does not accept prompts. OpenAI API key and Grok remain polish-only. The two-step polish pass is `SettingsService.refinementProvider`, which may be any `CloudProvider` (defaults to `cloudProvider` until chosen, key `refinement_provider`) and only ever receives transcript text.
- Desktop and mobile single-pass dictation use `CloudTranscriptionService.transcribeSinglePass` on `cloudProvider` + `selectedModelId`: dedicated speech models call `transcribeAudio` once without a writing-style request; audio-capable prompt models call `transcribeAndImprove` once.
- `GeminiModelConfig.supportsAudio` marks real audio input per model; `AppConfig.audioModelsForProvider` filters it provider-aware (Vertex excludes the dedicated Gemini speech model) and is gated to `firstPassAudioProviders`. Codex's only audio model is `chatgpt-transcribe`. `SettingsService.primaryModels` (= audio models of `cloudProvider`) is the first-pass list and is stable across the two-step toggle and polish-provider changes. Saved offered model preferences survive provider/pipeline switches; incompatible contexts resolve safely without erasing the stored preference. Keep `promptIsApplied` and selector guidance aligned with this routing.
- Every style-selection surface gates on the same rule: `promptSelectableInModePopup` (exported from `widgets/mode_selection_popup.dart`) — Default always selectable, everything else requires `SettingsService.promptAppliesFor(prompt)` (per-prompt, so a style forcing two-pass stays selectable when the global pipeline cannot apply styles). The tray menu, the Ctrl+Shift+M popup (tiles, keyboard stepping via `nextSelectableModeIndex`, and the Enter guard in `_selectModeByIndex`, which must run before hotkey teardown), and the mobile pickers must never drift from it; the popup shows `modePopupLockNotice` copy explaining the way out.
- Custom-style creation lives in `PromptsPage._showPromptDialog` (desktop only; mobile picks but does not create). In create mode a dialog-local `baseId` ('' = Blank) drives a 'Start from' dropdown that seeds the instruction from a built-in and auto-suggests `<Base> (custom)` only while the name is empty or still the previous auto-suggestion (`autoName` guard) — a user-typed name is never clobbered. The edit dialog renders no selector. Per-style model binding does not exist: styles carry only instruction text; model/pipeline choice stays in the transcription settings.
- Two-step refinement runs through `CloudTranscriptionService.transcribeTwoPass` (shared by desktop and mobile): pass 1 = `cloudProvider` + `selectedModelId` via `transcribeAudio`; pass 2 = `refinementProvider` + `twoPassRefinementModelId` over `refinementModels` (prompt-capable; per-provider storage keys). The Whisper-backend polish path calls `refineTranscript(settings:)` (same pass-2 stage). `isTranscriptionReady`/`transcriptionSetupIssue` gate recording on the credentials of every stage in use and give the user-facing reason. Never resolve a text-only model into the audio stage. Both two-pass entry points accept `pass1ModelOverrideId`/`polishModelOverrideId` (`refineTranscript`: polish only) — null means settings-resolved; overrides still pass the same stage validation.
- Custom styles may carry pipeline overrides (`SystemPrompt.modelOverrideId`/`polishModelOverrideId`/`twoPassOverride`, null = follow global; persisted only when non-null, so old JSON loads as all-null). `SettingsService.resolvePipelineForPrompt` is the single resolver (`PromptPipeline{twoPass, pass1ModelId, polishModelId}` — overrides honored only within `primaryModels`/`refinementModels`, else safe fallback to global; whisper backend ignores pass1 id); `promptAppliesFor(prompt)` is the per-prompt applicability rule (equals global `promptIsApplied` for null-override prompts); `pipelineReadyForPrompt`/`pipelineIssueForPrompt` gate recording on the effective stages' credentials. Desktop (`main.dart` `_stopRecordingAndProcess` + the start gate and mode-popup Enter path) and mobile (`mobile_transcription_controller`) resolve the pipeline from the session's effective prompt and thread the ids into the service calls; backend (cloud/whisper) stays global — overrides never switch backend or provider. `PromptsPage._showPromptDialog` edits the overrides (Follow-global defaults, validity-safe pickers, live not-applied/credential warning); rows show a tune icon and Current Style an "Own pipeline · …" summary when overrides exist.
- Upgrade migration (`SettingsService._migrate`): a stored text-only `cloud_provider` from older releases moves to `refinement_provider`, enables two-step, and promotes the legacy `two_pass_cloud_provider`/`two_pass_transcription_model_id` first pass (Gemini fallback); those legacy keys are then retired.
- Thinking levels are stored per model **and per pass**: `getThinkingLevelForModel`/`setThinkingLevelForModel` (`thinking_level_<id>`) are the first pass; `getRefinementThinkingLevel`/`setRefinementThinkingLevel` (`refinement_thinking_level_<id>`) are pass 2, so the same model in both passes never couples levels. The service resolves the pass-2 level explicitly before calling `improveTranscription`; OpenAI/Codex/Grok client fallbacks read the refinement key. `transcribeAudio` accepts a `thinkingLevelOverride`; null keeps the fastest (lowest) level. A one-time `refinement_thinking_split` migration copied existing levels to both passes.
- Model catalogs live in `AppConfig` (`config.dart`): Gemini/Vertex share `availableModels`; `openAiModels` and `codexModels` share the GPT-6/GPT-5.6 family via private consts and mirror the codgine repo's OpenAI/Codex provider (`gpt-6-astra/sol/luna`, `gpt-5.6-sol/terra/luna`, `gpt-5-6-thinking`, `gpt-5.5`, `gpt-5.4`, `chat-latest`). No `*-codex` model ids remain. Per-model UI copy is `GeminiModelConfig.description`, not a switch in the widgets.
- `GeminiThinkingLevel.none` ("Off") maps to `reasoning_effort`/`reasoning.effort: none` and is listed by GPT-5.x models plus GPT-6 Sol/Luna (GPT-6 Astra starts at `low`, matching codgine). `xhigh` ("X-High") and `max` are listed by GPT-6 Astra/Sol/Luna and GPT-5.6 Sol/Terra/Luna (as in codgine) and go on the wire by name (Grok clamps them to `high`); levels persist by `apiValue`, so append new enum values freely; the GPT-5.5+ family rejects `minimal`. No Gemini model offers `none`.
- Provider UI copy comes from `CloudProviderExtension` (`enums.dart`: `displayName`, `description`, `credentialLabel`) plus `CloudProviderPresentation` (`widgets/settings/cloud_provider_presentation.dart`: `icon`, `tagline`). Desktop settings (`AiModelsPage`) use only Bee widgets: the step-1 "Transcription Account" is a `BeeSettingsRow` with a `BeeSegmented<CloudProvider>` (key `transcription-provider`) over `firstPassAudioProviders`, matching the Engine row; step 2 is a `BeeDropdown<CloudProvider>` row (key `two-pass-refinement-provider`) followed by that provider's credential rows (skipped when it shares the step-1 account), the polish model and "Polish thinking" rows. Connection status is tracked per provider. Onboarding renders tiles from `firstPassAudioProviders` only. Mobile uses Material widgets; its pass-2 section is `PolishStepSettings` (`widgets/settings/first_pass_settings.dart`).
- Gemini 2.5 uses `thinkingBudget: 0` on Vertex. The Interactions API uses named levels instead: restored 2.5 Flash defaults to `low`, while 2.5 Flash-Lite leaves its default thinking off. Do not send numeric thinking budgets in Interactions payloads.
- Transcript auto-paste awaits the clipboard write, then calls `KeyboardService.simulateCtrlV(waitForModifiers: false)`. Keep fixed pre-paste timers out of this path and retain the native modifier-release events. Windows paste tests inject `sendInput` so tests never synthesize real keyboard input.
- The Windows runner installs `beeamvo::HotkeyPlugin` after generated plugins to replace the stock hotkey-manager channels with compatible key-down/key-up events. Pass the runner's `GetHandle()` explicitly: the Flutter view is not parented until `SetChildContent`, so capturing its `GA_ROOT` during plugin construction registers hotkeys on the wrong HWND. Preserve `MOD_NOREPEAT` and native hook cleanup. macOS uses its existing release callback; Linux still needs its hold-release timer fallback because its stock plugin emits only key-down.
- `RecordingStartGate` retains stop requests while the recorder starts. Enter/Escape are registered before capture initialization; cancellation invalidates the session token so queued stops cannot process superseded sessions.
- WAV readiness checks use finalized RIFF length as the immediate path and cache the probe across stop/read. Retain bounded fallback handling for unfinished files.
- Native Windows verification: `flutter build windows --debug --no-pub` from `frontend/` (verified with the local Visual Studio toolchain).
- Debug latency diagnostics use `[TranscriptionTiming]` for desktop audio preparation/delivery, `[CloudTranscription]` for model/provider/stage timing, and `[TranscriptionRequest]` for HTTP attempts/backoff. Do not log audio, transcripts, prompts, API keys, or upstream response bodies when extending diagnostics.
